Serviceportal für Handwerksbetriebe

Ein Anfrage-Workflow für einen fiktiven Elektrofachbetrieb — vom Formular bis zur Bearbeitung im WordPress-Admin.

Statische VorschauGitHub-Repository

Die öffentliche Vorschau versendet keine Anfrage. Der folgende Admin-Workflow wurde in einer lokalen WordPress-Testinstallation mit fiktiven Daten geprüft. Die überarbeiteten Dateien liegen im gelieferten Projektpaket; GitHub kann noch den vorherigen Stand zeigen.

Aufgabe, Zielgruppe und Rolle

Ein möglicher Interessent soll eine Serviceanfrage strukturiert erfassen; ein Betrieb soll diese im Admin bearbeiten können. Eigene Praxisarbeit: Theme, Funktionsplugin, Formular und Prüfung. Kein Kundenprojekt.

Funktionen und Architektur

  • Mehrstufiges Formular mit Zusammenfassung und optionalem Foto.
  • Private Anfragen mit Status, Notizen, Filter und CSV-Export im Admin.
  • Theme für Darstellung; separates Plugin für Verarbeitung, Daten und Rechte.
Theme / Formular → Plugin-Hooks & PHP-Validierung → WordPress-API → Custom Post Type + Post-Metadaten (wp_posts / wp_postmeta)

Die Speicherung erfolgt über WordPress, nicht in einer selbst entwickelten Datenbank. Ein admin-post.php-Handler verarbeitet die Anfrage; Nonce, Eingaben und Datei werden serverseitig geprüft.

Entscheidungen

  1. Plugin statt Theme-Logik: Anfrageverarbeitung bleibt vom Layout getrennt.
  2. Validierung vor Speicherung: Dateigröße und Bildtyp sowie Pflichtfelder werden auf dem Server geprüft; ein fehlgeschlagener Upload soll keinen erfolgreichen Vorgang vortäuschen.
  3. Eigene Berechtigungen: Private Anfragen sind nicht automatisch für redaktionelle Rollen sichtbar.
  4. JavaScript als Ergänzung: Schritte, Fehler und Zusammenfassung erleichtern die Eingabe; die serverseitige Prüfung bleibt entscheidend.

Nachweis: Ablauf im lokalen WordPress

Lokale Testinstallation, fiktive Daten, automatisierte Aufnahme per Playwright: Formular → Adminliste → Status und Notiz speichern.

Prüfung und Grenzen

PHP-Unit-artige Einzeltests ohne WordPress und Integrationstests in einer lokalen WordPress-Installation prüfen unter anderem Validierung, Uploads, Rollen, CSV und Status. Details und ein reproduzierter Fehler: QA-Bericht.

Die statische Vorschau hat kein PHP-Backend und ist kein produktives Anfrageformular. Kein Nachweis für kommerzielle Nutzung oder reale Kundenprozesse. Die lokale Konfiguration muss Uploads bis 5 MB zulassen.
